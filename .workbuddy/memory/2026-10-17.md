## EPUB 导出兼容性诊断（京东读书/微信读书打不开）

- 实测（kitchen-sink 样本导出 + Python 严格 XML 解析 + zip 结构校验）：mimetype 首条目 STORE / container / OPF / manifest / spine / ncx 锚点 / UTF-8 无 BOM / 全部 XML 条目格式良好——**容器层完全合规**，「EPUB 2 保守策略」防守错了对象。
- 最可能根因（内容层，与主流工具做法相反）：
  1. 导入型书籍图片经 inlineImages（默认 true，from-epub.ts:300）变 data URI，exporter 原样写回 XHTML → RMSDK data URI 兼容差 + base64 膨胀 + 平台体积限制；自建书图片 src 是本地/外链 → 死链。exporter 零媒体收集。
  2. style.css 全量 CSS Variables + var()（book-css.ts），RMSDK/微信读书老引擎不支持 var() → 样式整体丢弃（能打开但无排版）。
  3. 元数据非平台习惯：identifier=urn:bibliotype:hash（非 ISBN/UUID）、无封面 meta 声明。
  4. 「2.0 OPF + 无 properties 的 nav.xhtml + XHTML1.1 DOCTYPE 含 HTML5 nav 元素」非标准混合态；docs/07 还写 EPUB 3，已与代码漂移。
- 已给改造清单（P0 媒体打包/封面约定/导出前校验器/元数据；P1 CSS 扁平化/样式空洞/直排降级/版本策略/文档壳；P2 体积/分节/导入侧对称/真机矩阵），等用户确认再动手。
- 环境备忘：本会话 Bash 工具 PATH 损坏（无 coreutils），PowerShell stdout 被吞——用「写文件 + Read 工具读」模式执行命令；PowerShell 删除受 safe-delete 守卫（转 trash 失败即报错），临时文件用 Get-ChildItem -File | ForEach-Object Remove-Item 逐个删。

## 编辑卡顿归因（分析，未改动）

- 落盘侧确实有洞：`use-draft-autosave` 的 `requestIdleCallback({timeout: 2000})` 在浏览器持续忙碌时**强制**执行，落在按键帧上；`IndexedDbAdapter.save` 是整本 `put`（结构化克隆在主线程，量级≈文档体积，1.8MB ≈ 27ms）。delay 1200/maxWait 15000 → 连续编辑约每 1.2s 一次的 20~40ms 长任务。

- 结论：两个来源量级接近，必须先加 longtask 归属探针再改，禁止直接调参了事。

### 顺带查实的三处具体缺口（可直接改）

1. `book-css.ts` 只有 `.bt-heading` 一条规则（字号单一 token），序列化器却输出 `h1..h6.bt-heading` → 标题无法分级设样式，需拆 6 条 + 留 `.bt-heading` 兜底。

## 编辑态分页无法放大（缩放）修复（2026-10-17）

**现象**：编辑模式下工具栏「缩小 / 放大 / 按宽度缩放整页」按钮无效，页面不能放大。

**根因**（`DEFAULT_EDITING_SETTINGS.pagination = true` → demo 走 paged 内核）：
- `BtEditor.scale` 此前只作用于「连续画布」（`v-show="!pagedActive"` 的 `pageZoomStyle`），
  **分页态根本没把 `scale` 透传给 `PagedCanvas`**；
- `PagedCanvas.updateScale()` 的自适应公式 `Math.min(1, available / pageWidth)` **硬上限 1**，
  只能缩到容器宽、永远 ≤100%，结构上杜绝放大。
- 两处叠加 → paged 编辑态缩放整体失效（demo 绑的 `:scale="editorScale"` 被直接忽略）。

**修复**（`packages/vue`）：
- `PagedCanvas.vue`：新增 `scale?: number | null` prop；`scrollScale` 由 ref 改为
  **计算属性** `userScale.value ?? fitScale.value`（`userScale` 限幅 0.2~2，允许 >1；
  `fitScale` 仍走原 DOM 实测自适应）。关键：改计算属性是为了**首帧即生效**——早先只在
  `onMounted(updateScale)` 里赋值，`@vue/test-utils` 首帧渲染读到的仍是 `scale(1)`，需 nextTick
  才更新；计算属性让纯响应式的用户倍率不依赖挂载时序。`updateScale()` 用户倍率命中时直接
  return 不再量尺；`watch([scale, fit])` 驱动来源切换。
- `BtEditor.vue`：paged 分支加 `:scale="props.scale === undefined ? undefined : resolvedScale"`
  ——**不传 scale 时透传 undefined 保留自适应**（向后兼容库消费者），传了才覆盖。

**边界**：demo 恒绑 `:scale="editorScale"`（缺省 1）→ paged 编辑默认按原生 100%（与连续画布
一致），页宽超出容器由 `.bt-editor__scroll{overflow:auto}` 横向滚动承接；缩小/放大/适应宽度均生效。

**验证**：`packages/vue` vitest 81/81（新增 1 例：scale 覆盖自适应 + 限幅 2 + 还原 undefined 回退）；
`vue-tsc --noEmit` EXIT=0。跨包/demo 需重建 `@bibliotype/vue` dist 方能在浏览器看到效果。

## 编辑输入时同一段落跨页重复渲染修复（2026-10-17）

**修复**（`packages/vue`）：

- `selection-bridge.ts`：`charOfLine` 越界改为按平均行宽外推 `last + (line - lastIdx) * avg`（单点退 charsPerLine），

## 【新任务】分页编辑态工具栏命令批量修复

用户反馈（paged 编辑态）：引用/无序/有序/版框/表格/边注无效果；双行注/校勘记需点很多次才能输入；

部分命令点击后视口跳到前后几页（文档未说，疑 bug）。

**统一根因**（都在「命令走 binding.execute、片段编辑走 PagedCanvas 内部」这条分界）：
1. 命令经 execute→applyTransaction→version++→重排，但**不置位 restorePending**（只有片段编辑才置），

2. 片段选区→模型经 selectionchange 的 rAF 去抖，移光标后立即点按钮→模型 selection 落后 DOM 光标几字符→
   出校符号等就地插入随机偏移。
3. 命令事务带 .scrollIntoView()；paged 下 applyTransaction 仍对**隐藏 PM 视图** updateState→隐藏视图 scrollIntoView
   滚外层→视口莫名跳页。

**修复**：
- `use-editor.ts`：EditorBindingOptions 新增 `syncView?: () => boolean`；applyTransaction 仅 `!== false` 时 view.updateState。
- `PagedCanvas.vue`：defineExpose 增 `flushSelectionSync()`（cancel selRaf+syncSelectionToModel）与 `requestCaretRestore()`（置 restorePending）。
- `BtEditor.vue`：useEditorBinding 传 `syncView: () => !pagedActive.value`；新增 pagedCanvasRef 模板 ref；
  `runPagedAware`（paged 且可编辑时：先 flushSelectionSync→action→成功 requestCaretRestore）包装 slotBinding 的
  execute/undo/redo；`<slot v-bind="slotBinding"/>`；需 import type Command + type EditorBinding。

**未改（语义/特性说明）**：眉批/跋文落点「当前叶块之后」是命令契约，版心外视觉落位为分页后续特性（非回归）；
