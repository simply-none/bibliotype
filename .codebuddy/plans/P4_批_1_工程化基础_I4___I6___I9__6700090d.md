## 用户需求

执行 `P4-执行分批清单.md` 的批 1（工程化基础 3 项），每项达到仓库完成定义「导出符号 + 测试（含负例）+ `docs/` 回写 + changeset」四项齐备后勾选 `[x]`。

## 产品概述

- **I4 覆盖率门槛**：v8 provider 统一覆盖率配置；core/layout/reader 设阈值拦截，其余包只报告不拦；CI 产出并归档报告；排除 `__tests__`/fixtures/类型声明。
- **I6 VERSION 自动化**：`scripts/version.mjs` 单源写回各 `package.json` 与 `packages/core/src/version.ts`；`release:check` 增一致性断言；幂等测试。
- **I9 SSR/Node 矩阵**：CI Node 20/22 矩阵；关键包（core/layout/import/exporter/reader）补 node 环境导出冒烟测试；docs/15 标注各包 SSR 可用性。

## 验收标准

- `pnpm test:coverage` 生成报告，低于阈值 CI 失败并指出文件。
- 改版本后 `version.ts` 与 `package.json` 一致；不一致时 `release:check` 失败；版本脚本二次运行无 diff。
- Node 20/22 CI 全绿；node 环境 import 关键包不报 `document is not defined`。
- 收尾同步：`P4-执行分批清单.md` 批 1 勾选、`能力扩展实施计划清单.md` 台账 I4/I6/I9 状态更新、changeset、一条合并 Conventional Commits 中文提交信息。

## 技术选型

沿用现有栈：pnpm@9 workspace + turbo + vitest 2.x + tsup + GitHub Actions；新增依赖仅 `@vitest/coverage-v8@^2.1.0`（与 vitest 2.1 对齐）。不引入新包、不越界。

## 实施方案

### I6 VERSION 自动化（先做，其余两项不依赖它但 changeset/发布链路会用到）

- `scripts/version.mjs` 重构：把主流程收进「仅直接执行时运行」守卫（比对 `import.meta.url` 与 `process.argv[1]`），使文件可被测试导入；新增 `updateCoreVersionTs(version)`（正则替换 `packages/core/src/version.ts` 的 `VERSION` 字面量，保留其余内容），在写完 `package.json` 后调用；导出 `updateVersionField` / `updateCoreVersionTs` 等纯写函数供幂等测试复用。
- 新增 `scripts/check-version.mjs`：断言全部公开包 `package.json` 版本一致，且 `core/src/version.ts` 的 `VERSION` 与之一致；不一致时非 0 退出并指出漂移文件。挂入根 `release:check` 前置：`node scripts/check-version.mjs && pnpm build && pnpm -r publish --dry-run --no-git-checks`。
- 测试：`packages/core/src/__tests__/version-sync.test.ts`——① 导入源码 `VERSION` 与 `packages/core/package.json` 对账；② 遍历 `packages/*` 断言版本列车一致；③ 通过 `child_process` 运行 `node scripts/check-version.mjs` 断言退出 0；④ 对 tmp 目录复制的 fixture 连续两次调用写回函数，断言二次无 diff（幂等，含负例：人为改坏 `VERSION` 时 check 脚本非 0）。

### I4 覆盖率门槛

- 新增共享配置 `vitest.shared.ts`（仓库根）：导出 `createVitestConfig({ coverage })` 工厂，统一 `coverage.provider: 'v8'`、`include: ['src/**']`、`exclude: ['**/__tests__/**', '**/fixtures/**', '**/*.d.ts', '**/dist/**']`、reporter `['text', 'lcov']`。
- `core` / `layout` / `reader` 各新增 `vitest.config.ts` 引用共享工厂并带阈值；**阈值不拍脑袋**：先跑一次真实 `vitest run --coverage` 取基线，按基线略下调设定（宁低勿假绿），写入配置。
- 其余有测试的包不加配置文件：`test:coverage` 脚本走 CLI `vitest run --coverage`（只报告不拦）；`editor` 已有 `vitest.config.ts` 保持不动（prosemirror 双实例修复不可破坏），仅 CLI 跑覆盖率。
- 各包新增 `test:coverage: vitest run --coverage` 脚本；根新增 `test:coverage: turbo run test:coverage`（turbo 任务新增 `test:coverage`，`dependsOn: ["^build"]`，与 `test` 同构）；受影响包 devDeps 加 `@vitest/coverage-v8`。

### I9 SSR/Node 矩阵

- `.github/workflows/ci.yml`：`verify` job 增 `strategy: { fail-fast: false, matrix: { node-version: [20, 22] } }`，`setup-node` 与 job name 引用矩阵值；保留既有步骤与 E9 CLI 护栏。
- 追加 coverage 步骤：`pnpm test:coverage` 后用 `actions/upload-artifact@v4` 归档 `coverage/lcov.info`（artifact 名带 Node 版本）。
- 关键包各新增 `src/__tests__/exports.test.ts`（默认 node 环境）：动态 `import()` 包入口（源码路径），断言关键导出存在且顶层不触发 DOM（对 `typeof document === 'undefined'` 前后无异常）。覆盖 `core` / `layout` / `reader` / `import` / `import-epub` / `import-docx` / `exporter-epub` / `exporter-pdf` / `exporter-site`；实现前先甄别各包顶层是否确无 DOM 依赖，若某包顶层确有 DOM 依赖则跳过并在 docs/15 标注「Node 不可用」，不硬造绿色。
- `docs/15-ssr-and-node.md` 补各包 SSR 可用性标注表（可用/受限/不可用 + 原因）。

## 性能与可靠性

- 覆盖率仅增量 devDep，不改运行时；阈值拦截失败信息由 vitest 自带（指出文件）。
- 版本写回用正则替换保持文件格式零 diff；`check-version.mjs` 幂等可重复执行。
- CI 矩阵会使构建时长约 ×2，属可接受范围（S 级改动）。

## 架构约束

- 不改 editor 既有 vitest 配置的 prosemirror 修复逻辑；DOM 环境继续走测试文件内 `// @vitest-environment happy-dom` 注释，不全局切环境。
- 依赖方向不变；turbo 任务与现有 `test` 同构，缓存友好。
