## 优化「编辑 → 保存」链路（大文档编辑卡顿）

**背景**：编辑时卡顿。实测（78 万字 / 12623 块，仓库自带验收规模）定位到两个主线程同步大任务。

**实测数据（改动前 → 改动后）**
- 逐键 dispatch（有 onChange 订阅）：5.01 ms → 0.74 ms（无订阅基线 0.25 ms）
- `getDocument()` 全量 PM→IR：4.80 ms → 未变；`getSharedDocument()` 增量：0.02 ms
- 整本文档 1.78 MB：JSON 8.8 ms / structuredClone 26.7 ms（IndexedDB put 口径）
- `extractBlocksIndexed` 全量：6.25 ms（每轮重排由 3 次降为 2 次）

**根因**
1. `BookEditor.emitChange()` 每次 `docChanged` 事务同步全量 `getDocument()`（订阅方只读 `isDirty`）；
2. Demo 自动保存＝去抖 1.5 s 后整本落盘（快照 5 ms + 克隆 27 ms ≈ 32 ms 长任务），去抖又被逐键重置；
3. `buildPagedLayout` 每轮 3 次全树抽块；
4. 数据 bug：`markSaved()` 在 `await` 之后 → await 期间的新编辑被误标「已保存」。

**改动文件**

- `packages/editor/src/__tests__/editor.test.ts`：+3 例（同构 / 未变子树跨快照同引用 / 同源缓存）。
- `packages/vue/src/pagination-measure.ts`：`MeasureBlockSizesInput.extracted` 可选入参（复用预抽块）。
- `packages/vue/src/paged-editor/use-paged-layout.ts`：探针 / 量尺 / 索引共用一次结构抽取（3 → 2 次）。
- `packages/vue/src/__tests__/pagination-measure.test.ts`：+1 例（extracted 结果同源且块仍渲染）。

## 修复「含注音段落里行内标记落点右移」（字符坐标轴错位）

**现象**：编辑工具栏选中文字后点「异体」，标记落到选中内容右侧；前提是同段落中选中内容之前已有注音（ruby）。

**根因**：字符坐标轴不一致。模型轴（`reader.collectNodeText` / `layout` 的 `nodeTextLength`）只拼文本子节点，
**不含** ruby 注文（注文在 mark 的 `attrs.text`）；DOM 轴**含**注文——`html-serializer` 渲染为
`<ruby>基字<rt>注文</rt></ruby>`，`<rt>` 是真实文本节点。凡把 DOM 文本当模型偏移用，偏移多出「选中位置
之前的注文字数」→ 选区 / 光标 / 行首偏移整体右移。**同源两处**：`input-router.fragTextNodes`、
`pagination-measure.collectTextOffsets`（后者产出的 `lineOffsets` 同时喂 `sliceNodeByCharRange` 切片与选区映射）。

**改动文件**
- `packages/vue/src/ruby-annotation.ts`（新）：`isRubyAnnotationElement` / `isRubyAnnotationText` 原子模块（内部，不入 index）。
- `packages/vue/src/paged-editor/input-router.ts`：`fragTextNodes` 跳过 `<rt>`/`<rp>` 子树。
- `packages/vue/src/pagination-measure.ts`：`collectTextOffsets` 跳过注文文本节点（TreeWalker 逐点判祖先）。
- `packages/vue/src/__tests__/paged-input.test.ts`：+4 例（序列化契约 / `fragPlainText` / 选区不右移 / 往返）。
- `packages/vue/src/__tests__/ruby-annotation.test.ts`（新）：+3 例。
- `.changeset/vue-ruby-annotation-char-axis.md`（新）；`docs/14-faq.md` 新增第 7 条。

**验证**：vue 78 例（原 71 + 新增 7）通过；`vue-tsc --noEmit` exit 0；全仓 turbo `test` 25/25 通过。
**限制（已写入 FAQ）**：`lineOffsets` 依赖真实布局（`getClientRects`），happy-dom 无布局 → 单测覆盖不到，
含注音多行段落的切片边界需在 demo 手工确认。

**流程备注**：执行中发现同根因第二处，先向用户说明影响面（触及分页行为）并取得确认后才改——符合用户
「先对齐再动手」的既定流程。
