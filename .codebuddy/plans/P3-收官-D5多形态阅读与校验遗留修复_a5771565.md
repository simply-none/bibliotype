## 用户需求

修复「含古籍插件节点 / 标记的文档在整库备份恢复、历史版本回滚时被误判为非法文档」的遗留问题，并一次性完成 P3 最后一项 D5 多形态阅读。

## 产品概述

阅读器在既有「单页翻页」与「连续滚动（预分页窗口化）」之外，新增「流式阅读」形态：正文按章节分块，随滚动渐进挂载，大部头首屏只渲染当前可见的少量内容；阅读位置以正文锚点而非页码保存，字号或版式变化后仍回到原句；翻页带方向自适应动效，系统开启「减少动态效果」时自动关闭；新增双页对照视图，既可同书左右对页，也可左右并排比对两份文稿。

## 核心功能

- **备份 / 回滚修复**：含古籍节点与标记的书籍可从整库备份正常恢复、可正常回滚历史版本；恢复失败时才给出中文原因与路径。显式调用文档校验仍保持严格，未知类型仍报错。
- **流式阅读（新增阅读模式）**：按结构章节切块，仅挂载视口附近分块，离开视口后卸载；未挂载分块以估算高度的占位骨架撑起滚动条。
- **章节懒加载**：首屏只渲染当前章节与邻近少量分块，向下滚动按文档顺序渐进加载，不出现整本一次性渲染。
- **位置锚定**：阅读位置由「当前可见首块锚点 + 阅读进度」组成并持久化，刷新或改字号后回到原句；旧版仅存页码的数据自动兼容。
- **翻页动效**：横排左右滑动、直排方向自适应，约 220ms；支持关闭，尊重系统「减少动态效果」。
- **双页对照**：单文档时左右对页阅读；传入第二份文稿时左右并排、各自独立翻页并可同步页码，带「底本 / 校本」标签与中缝分隔。
- **降级规则**：直排、仿真版式、对页模式下流式阅读自动回退为分页渲染，并通知宿主提示原因。

## 技术栈

- 语言与运行时：TypeScript + Vue 3（`<script setup>`），构建用 Vite，测试用 Vitest + happy-dom，类型检查用 `vue-tsc`。
- 复用现有内核：`@bibliotype/core`（IR / 锚点 / 校验）、`@bibliotype/reader`（分页、块索引、位置快照）、`@bibliotype/layout`（`serializeNode` / 书册 CSS）。
- 不引入任何新运行时依赖：`IntersectionObserver` / `ResizeObserver` / `matchMedia` 均做存在性探测与降级。

## 实施策略

分两条独立线并行推进，最后在 demo 汇合：

1. **恢复链路校验修复（core）**：`ValidateOptions` 已支持 `knownNodeTypes` / `knownMarkTypes` / `unknownTypesAsWarning`（且与 core 内置类型合并，传插件类型不会丢 core 类型）。因此不需要新机制，只需把选项从恢复入口透传到 `validateDocument`，并让**恢复路径默认宽容**（`unknownTypesAsWarning: true`），显式校验保持严格。这样既修掉「古籍文档恢复被拒」，又保留拼写错误的检出能力，同时不改变任何既有函数签名（只增加可选参数 / 可选属性）。
2. **流式阅读（reader + vue）**：新增 `buildFlowChunks` 纯函数把 IR 切成「章 + 分块」的扁平列表，`Reader` 提供按节点取位置的能力；视图只用已挂载 chunk 做序列化，用估算高度占位、挂载后实测校正，滚动时以「视口首块」回写位置。

### 关键技术决策

- **为什么新开 `mode="scroll-flow"` 而不是改 `scroll`**：现有 `scroll` 依赖一次性预分页结果（`pagination` + `getPageFragments`），是「窗口化分页」，改它会同时冲击分页体积、注区、对页与既有测试。新模式只读 IR 块序列，与分页互不依赖，可独立回退。
- **为什么分块而不是按节点虚拟化**：逐块虚拟化会让高度估算误差累积到每一段；以「24 块 / 1200 字」为上限切块，单块高度误差可控，且懒加载粒度足够（一章通常 3~10 块）。
- **为什么估算 + 实测校正**：不对 1000 页文档做全量测量才能真正「替代一次性预分页」；骨架高度按「字数 / 每行字数 × 行高」估算，挂载后 `ResizeObserver` 回写真实高度，并对上方变化做滚动补偿，避免跳动。
- **为什么锚点而非页码**：`reader/src/position.ts` 的 `createReadingPosition` / `parseReadingPosition` / `restorePosition` 已就绪但视图未用；接上后位置不再随字号、屏宽漂移。
- **为什么抽 `BtSpreadLayout`**：`BtBookView` 的 facing 几何、`BtCollationCompare` 的双栏对照各自实现了一遍两栏布局；抽成纯布局容器后，`BtCompareView` 与 K2 校勘对照共用同一套中缝、比例与响应式规则。

### 性能与可靠性

- 分块构建 O(n) 一次，按「文档引用 + 选项」缓存；文档替换才失效。滚动监听 rAF 节流，位置仅在首块变化时 emit（去重）。
- 已挂载 chunk 的 HTML 按「chunk key + 样式版本」缓存，避免每次滚动重复序列化；只序列化视口窗口，序列化量 O(视口) 而非 O(全书)。
- 高度修正合并到一次 rAF 内批量写回，避免 `ResizeObserver` 循环触发布局抖动；滚动补偿用「锚点块相对偏移」而非绝对 `scrollTop`。
- 能力缺失降级：无 `IntersectionObserver` 时挂载前若干块（可配置）；无 `ResizeObserver` 时保留估算高度；无 `matchMedia` 时视为「未开启减少动效」。
- SSR 安全：所有浏览器 API 只在 `onMounted` 之后访问，模块顶层不读 `window`。

### 兼容性与影响面

- `BtBookView` 的 `mode` 仅扩展联合类型，`page` / `scroll` 分支代码路径与产物不变；新 props 全部可选，默认 `pageTransition: 'slide'` 仅影响分页模式的过渡包装（不影响序列化产物与导出）。
- `restoreLibrary` / `restoreSnapshot` 增加可选参数；默认从「未知类型即失败」改为「未知类型降级告警」属于**有意的行为修正**，需在 changeset 与 docs 明确写出，并保留 `validate: false` 与 `unknownTypesAsWarning: false` 两条退路。
- `BtCollationCompare` 仅调整 facing 模式的外层容器，保留 `.bt-collation-compare__pane` / `data-role` 等既有选择器，确保现有测试与宿主样式不破。

## 实施要点

### A. 恢复链路校验（core）

- `RestoreLibraryOptions` 增加 `validateOptions?: ValidateOptions`；校验调用改为
`validateDocument(unpacked.document, { unknownTypesAsWarning: true, ...options.validateOptions })`。
- `restoreSnapshot(snapshot, options: { validateOptions?: ValidateOptions } = {})` 同口径；返回结构不变，仍是 `{ ok, code, issues, message }`。
- 只有 **error 级**问题才判失败；warnings 不影响恢复，但需通过返回值让宿主可见（`restoreSnapshot` 成功分支可附带 `warnings`，需保持向后兼容的可选字段）。
- demo 侧集中一份 `DEMO_VALIDATE_OPTIONS`（classical 节点 + 标记类型），在三处调用点传入；不把 classical 依赖下沉到 core。

### B. reader 流式分块与位置

- `buildFlowChunks(document, { maxBlocksPerChunk = 24, maxCharsPerChunk = 1200 })`：结构容器（volume / chapter / section / preface / postscript / appendix）作为章边界，章内按顶层子块切片；块不可再分，避免把表格、注文切碎。
- `FlowChunk` 携带 `key`、`containerId`、`title`、`level`、`nodeIds`（块 id）、`startIndex`、`charCount`；无 id 节点用文档序号合成稳定 key。
- `Reader` 新增 `getFlowChunks(options?)`、`getNode(nodeId)`、`getBlockIndex(nodeId)`、`getPositionForNode(nodeId, { savedAt? })`、`getFlowChunkIndex(nodeId)`（含容器 id → 所在块）。
- 位置口径：`progress = 块序号 / 总块数`，锚点用 `createBlockAnchor(nodeId)`，与既有 `restorePosition` 完全兼容。

### C. vue 流式视图

- `flow-model.ts` 纯函数：`estimateFlowChunkHeight`、`resolveMountWindow`、`resolveAnchorChunkIndex`、`adjustScrollOffset`，全部无 DOM 依赖，便于单测与宿主覆盖。
- `BtBookView` 新增 props：`initialPosition`、`pageTransition`、`flowChunkBlocks`、`flowRootMargin`、`estimateFlowHeight`；新增 emits：`update:position`、`mode-fallback`。
- 流式分支：`section[data-flow-key]` + 骨架占位；挂载后用 `ResizeObserver` 修正高度并做滚动补偿；`initialPosition` 解析后强制挂载目标块并在 `nextTick` 后滚到 `#nodeId`（序列化开启 `anchorIds`）。
- 注释交互：`useNoteInteraction` 增加可选 `onLocateNode`，`goToNote` 优先调用它；流式模式传入「挂载 + 滚动到节点」，分页模式不传时行为不变。
- 键盘：`PageDown` / `Space` 按视口高度滚动，`Home` / `End` 到首尾；与 `Alt+←/→` 注释快捷键的优先级保持现状（注释先消费）。
- 降级：直排 / 仿真 / facing 时渲染 paged 分支并 emit `mode-fallback`，同时在根节点加 `data-mode-fallback="paged"` 便于宿主样式提示。

### D. 翻页动效

- paged 分支包 `<Transition :name="transitionName">`，key 为「页对起始页 + 页码」；`slide` 用 CSS 变量 `--bt-turn-x` / `--bt-turn-y` 控制入场方向，`fade` 只做透明度。
- 时长 220ms、缓动 `cubic-bezier(0.22, 0.61, 0.36, 1)`；`prefers-reduced-motion: reduce` 或 `pageTransition === 'none'` 时 `transition: none`。
- 过渡只加在页框外层，不改变 `serializeNode` 产物与导出 HTML。

### E. 双页对照

- `BtSpreadLayout`：props `{ mode, gap, leftLabel, rightLabel }`，插槽 `left` / `right`，`data-mode` 与中缝分隔线，scoped 样式。
- `BtCompareView`：`right` 缺省退化为 `BtBookView spread="facing"`；提供时左右各一 `BtBookView`，`syncPages` 双向同步（重入守卫 + 越界钳制），并汇总两侧位置 emit。
- `BtCollationCompare` 的 facing 改用 `BtSpreadLayout` 承载每个配对，保留既有类名与 `data-role`。

## 关键代码结构

```ts
/** 流式分块（reader 导出） */
export interface FlowChunk {
  /** 稳定 key（无 id 节点按文档序号合成） */
  key: string;
  /** 所属结构容器 id（章 / 节）；顶层块为合成 key */
  containerId: string;
  /** 章节标题（用于无障碍标签与占位文案） */
  title?: string;
  /** 结构层级（0 起） */
  level: number;
  /** 块节点 id（按文档顺序） */
  nodeIds: string[];
  /** 文档内块序号起点 */
  startIndex: number;
  /** 字数（高度估算与进度用） */
  charCount: number;
}

export interface BuildFlowChunksOptions {
  maxBlocksPerChunk?: number; // 默认 24
  maxCharsPerChunk?: number;  // 默认 1200
}

export function buildFlowChunks(
  document: BookDocument,
  options?: BuildFlowChunksOptions,
): FlowChunk[];
```

## 设计取向

延续「纸书」基调：流式阅读看起来像一条连续的纸面，而不是一叠卡片。行宽与字号沿用书册令牌，视觉重点仍是正文；骨架、分隔与控件一律低对比，避免打断阅读。

- **流式版面**：单列居中，最大行宽 38em；段间距 0.9em，首行缩进 2em（横排）；顶部与底部各留 24px 呼吸区；滚动条细窄（6px）并随主题取色。
- **占位骨架**：与正文同色的 6% 透明度色块，行高与真实行高一致（首行略短 60%，模拟段首缩进），不加动效扫光；`aria-hidden`，容器在挂载期间 `aria-busy="true"`。
- **渐进挂载**：进入视口前后各预留 800px 预挂载，挂载时淡入 120ms（高度不参与过渡，避免抖动）；已挂载块离屏 2 屏后卸载。
- **翻页动效**：横排新页自右向左滑入 12% 位移 + 透明度 0.6→1，220ms，缓动 `cubic-bezier(0.22,0.61,0.36,1)`；直排改为自下而上；退出页同向滑出并淡出。系统「减少动态效果」或显式关闭时完全瞬时切换。
- **双页对照**：两栏等宽，中缝 1px 低对比分隔线 + 24px 间距；顶部各一条 12px 小标签（底本 / 校本），标签不参与滚动；同步翻页时两栏同时过渡，方向一致。
- **状态提示**：流式不支持（直排 / 仿真）时在正文上方显示一条 12px 的说明条（「当前版式使用分页阅读」），可手动关闭；不使用弹窗。
- **无障碍**：分块 `section` 带 `aria-label`（章节标题）；位置变化沿用既有 `aria-live` 页码播报（流式下播报百分比）；键盘焦点进入正文时保留 1px 内描边。
- **响应式**：窄窗（<720px）流式行宽自动铺满并收窄左右内边距至 16px；对照视图在窄窗切换为上下堆叠，标签保留。
