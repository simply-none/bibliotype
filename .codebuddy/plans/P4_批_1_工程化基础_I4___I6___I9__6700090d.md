## 产品概述
执行 P4 批 2「质量门禁」两项（依据 `能力扩展实施计划清单.md` 第七部分与 `P4-执行分批清单.md` 批 2），每项满足仓库完成定义「导出符号 + 测试（含负例）+ docs 回写 + changeset」。

## 核心功能
### I8 统一错误码（M）
- core 新增 `BibliotypeError` 基类：`code`（稳定错误码）/ `details`（结构化上下文）/ `hint`（修复建议）/ `cause`（错误链）
- 五类既有错误继承基类并保留兼容字段与构造签名，不破坏现有 `instanceof` 断言：`HttpAdapterError`（adapter-http，status/path 保留）、`PluginConflictError` / `NodeTypeConflictError` / `MigrationPathError`（core）、`EditorSpecConflictError`（editor）
- 与 core 既有错误码先例（`CryptoError` + `CRYPTO_ERROR_CODES` + `isCryptoError`，H5 交付）同构对齐，不另造风格
- 错误码表进 docs/13，避免字符串漂移；导出 `isBibliotypeError()` 与序列化/反序列化
- 测试：code 稳定、序列化往返（含 cause 链）、旧 instanceof 与字段断言仍通过、非错误值负例

### I3 体积预算（S）
- 引入 `size-limit` + `@size-limit/preset-small-lib`，三档阈值（core 最严，vue/editor 次之），阈值按 `pnpm size` 真实 gzip 基线略上浮设定（宁紧勿松）
- 根脚本 `pnpm size`；CI 在 build 后执行；超限时输出对比表并指出包名

## 技术栈
沿用现有栈：pnpm@9 workspace + turbo + vitest 2.1 + tsup + GitHub Actions；新增依赖仅 `size-limit` + `@size-limit/preset-small-lib`（根 devDependencies）。不新增包、不越界。

## 实施方案

### I8 统一错误码
- 新增 `packages/core/src/errors/bibliotype-error.ts`：
  - `BibliotypeError` 基类（`code` / `details` / `hint` / `cause`），构造函数内打**不可枚举品牌标记**（跨 esm/cjs 双实例下 `instanceof` 可能失效，`isBibliotypeError` 走 instanceof + 品牌标记双重判定，区别于现有 `isCryptoError` 的纯 instanceof）
  - `serializeBibliotypeError()`（含 cause 链递归、深度上限）/ `deserializeBibliotypeError()` 纯函数
  - 错误码常量表按既有 `CRYPTO_ERROR_CODES` 风格组织（域分组 + SCREAMING_SNAKE 码）
- 五类错误改继承：保留原构造签名与公开字段（HttpAdapterError 的 `status`/`path` 兼容保留，可同时写入 `details`）；`name` 维持原值
- 影响面已核实（16 个文件引用）：导出面在 core/editor/adapter-http 各 index.ts，测试断言集中在 4 个既有测试文件（自动兼容），classical/plugin.ts 一处使用不受影响；`CryptoError` / `BookPackError` 已有 `code` 字段，顺带改继承基类（最小 diff），使 `isBibliotypeError` 真正覆盖「任意包抛出的错误」
- 测试：core 新增 `errors.test.ts`（基类字段 / code 稳定 / 序列化往返 / cause 链 / 负例），adapter-http / editor 各补继承兼容断言（旧 instanceof + 字段）

### I3 体积预算
- 根 `package.json`：devDeps 加 `size-limit` + `@size-limit/preset-small-lib`；`scripts.size = "size-limit"`；根集中 `size-limit` 配置段（入口指向各包 `dist/index.js`，gzip 计量）
- 执行顺序：先装依赖跑一次 `pnpm size` 取真实 gzip 基线 → 三档阈值 = 基线 × ~1.1（core 最严、vue/editor 次之，layout/reader 等纯小包设宽松档或不拦）
- CI：`.github/workflows/ci.yml` 在 `pnpm build` 步骤后新增 `pnpm size` 步骤（超限时 size-limit 自带对比表并指出包名）
