## 优化「编辑 → 保存」链路（大文档编辑卡顿）

**背景**：编辑时卡顿。实测（78 万字 / 12623 块，仓库自带验收规模）定位到两个主线程同步大任务。

**实测数据（改动前 → 改动后）**
- 逐键 dispatch（有 onChange 订阅）：5.01 ms → 0.74 ms（无订阅基线 0.25 ms）
- `getDocument()` 全量 PM→IR：4.80 ms → 未变；`getSharedDocument()` 增量：0.02 ms
- 整本文档 1.78 MB：JSON 8.8 ms / structuredClone 26.7 ms（IndexedDB put 口径）
- `extractBlocksIndexed` 全量：6.25 ms（每轮重排由 3 次降为 2 次）

**根因**
1. `BookEditor.emitChange()` 每次 `docChanged` 事务同步全量 `getDocument()`（订阅方只读 `isDirty`）；
2. Demo 自动保存＝去抖 1.5 s 后整本落盘（快照 5 ms + 克隆 27 ms ≈ 32 ms 长任务），去抖又被逐键重置；
3. `buildPagedLayout` 每轮 3 次全树抽块；
4. 数据 bug：`markSaved()` 在 `await` 之后 → await 期间的新编辑被误标「已保存」。

**改动文件**

## 修复「含注音段落里行内标记落点右移」（字符坐标轴错位）

**现象**：编辑工具栏选中文字后点「异体」，标记落到选中内容右侧；前提是同段落中选中内容之前已有注音（ruby）。

**根因**：字符坐标轴不一致。模型轴（`reader.collectNodeText` / `layout` 的 `nodeTextLength`）只拼文本子节点，
**不含** ruby 注文（注文在 mark 的 `attrs.text`）；DOM 轴**含**注文——`html-serializer` 渲染为
`<ruby>基字<rt>注文</rt></ruby>`，`<rt>` 是真实文本节点。凡把 DOM 文本当模型偏移用，偏移多出「选中位置
之前的注文字数」→ 选区 / 光标 / 行首偏移整体右移。**同源两处**：`input-router.fragTextNodes`、
`pagination-measure.collectTextOffsets`（后者产出的 `lineOffsets` 同时喂 `sliceNodeByCharRange` 切片与选区映射）。

**改动文件**
- `packages/vue/src/ruby-annotation.ts`（新）：`isRubyAnnotationElement` / `isRubyAnnotationText` 原子模块（内部，不入 index）。
- `packages/vue/src/paged-editor/input-router.ts`：`fragTextNodes` 跳过 `<rt>`/`<rp>` 子树。
- `packages/vue/src/pagination-measure.ts`：`collectTextOffsets` 跳过注文文本节点（TreeWalker 逐点判祖先）。
- `packages/vue/src/__tests__/paged-input.test.ts`：+4 例（序列化契约 / `fragPlainText` / 选区不右移 / 往返）。
- `packages/vue/src/__tests__/ruby-annotation.test.ts`（新）：+3 例。
- `.changeset/vue-ruby-annotation-char-axis.md`（新）；`docs/14-faq.md` 新增第 7 条。

**验证**：vue 78 例（原 71 + 新增 7）通过；`vue-tsc --noEmit` exit 0；全仓 turbo `test` 25/25 通过。
**限制（已写入 FAQ）**：`lineOffsets` 依赖真实布局（`getClientRects`），happy-dom 无布局 → 单测覆盖不到，
含注音多行段落的切片边界需在 demo 手工确认。

**流程备注**：执行中发现同根因第二处，先向用户说明影响面（触及分页行为）并取得确认后才改——符合用户
「先对齐再动手」的既定流程。

**环境备注（本 session）**：bash shim 缺 `dirname`/`ls`/`tail`/`cd`；PowerShell 启动 `pnpm` 触发被拦截的 `wmic.exe`；
PowerShell 会话不回传 stdout。可行链路：`node <pnpm store 内 bin 路径>`（vitest / vue-tsc / turbo 均可直调）
+ 输出重定向到文件 + 去 ANSI 后写工作区临时文件再用 Read 读取。
（补充：bash shim 的 `rm` 亦不可用（safe-delete 依赖 `dirname`）；删文件用 PowerShell `Remove-Item`，
且**一次只删一个**——多条 `Remove-Item` 用 `;` 串起来会报 exit 1 且部分不生效。Glob 结果有缓存，

## 分析「编辑次工具栏很多按钮貌似没用」（仅分析，未改代码）

**交付**：`编辑次工具栏-功能失效分析.md`（仓库根）。方法：临时 vitest 探针逐命令实测（41 条命令各起独立
`BookEditor`，构造 2 字选区后执行，记录 ok/threw/changed/形状），另做切片形态、块 id/attrs 保留、
空光标载体、序列化产物 4 组定点探针。**探针与输出文件跑完已删；classical 21/21、layout 85/85 复跑通过。**

**6 条根因（均实测）**
1. **R1（P0）** 夹注/异体载体/避讳载体 **选中文字后必抛异常**：`insertInlineNodeWrapping`
   （`packages/editor/src/commands.ts:471`）用 `state.selection.content().content`；`Selection.content()`
   等价 `doc.slice(from,to,true)`，切片根是块级 `chapter`（`openStart=2`）→ 塞进 `inline*` 节点 →
   `Invalid content for node inline-note: <chapter(paragraph(...))>`。异常发生在 `dispatch` 之前 →
   无事务、无 version++、无重排 → 视觉上完全无反应。空光标分支正常。
   **修复已验证可行**：改取 `$from.parent.content.cut(from - $from.start(), to - $from.start())`。
   ⚠️ 坑：`Node.cut()` 返回**同类 Node**（不是 Fragment），必须走 `Fragment.cut`（`parent.content.cut`）。
2. **R2（P0）** 正文/H1/H2/H3 **清空块 id**：`setParagraph`/`setHeadingLevel` 走 prosemirror-commands
   的 `setBlockType`，`Transform.setBlockType` 以 `type.create(attrsHere, null, node.marks)` 重建
   （attrsHere=null → 属性整体归默认）；且 prosemirror-model@1.25 的 `hasMarkup` 已**不再对 `attrs==null`
   短路**（改为与 `type.defaultAttrs` 比较），所以"已经是段落"也会被重写 → 每次点都丢 id。
   影响分页索引 / selection-bridge / 增量重排 hint / EPUB 锚点。对照：`toggleQuote()`（`wrapIn`）保留 id ✓。
3. **R3（P1）** **H1 渲染成 h2**：spec `level.default = 1`（`core-node-specs.ts:55`），IR 侧「等于默认值
   则省略」→ `level=1` 丢失；序列化器回退值却是 `2`（`html-serializer.ts:104`）。H2/H3 正常。
4. **R4（P1）** 印章/鱼尾/版框/夹注/异体载体/跋文 **无 `.bt-*` 样式**：印章印文只在 `attrs.text` →
   `<span class="bt-seal" data-text="印"></span>` 空元素 + 无 CSS → 完全不可见；鱼尾
   `insertBlockOfType(..., embedParagraph=false)` 空原子 + 无 CSS + **不移动光标**；避讳载体有 CSS
   而异体载体没有（不对称）。有样式的：双行注/眉批/校勘记/牌记/题记/脚注/尾注/边注/出校符号
   （`.bt-collation-mark::after{content:attr(data-symbol)}`）/避讳载体。
5. **R5（P1）** **分页态丢标记继承**：`edit-applier.ts:40` `state.schema.text(text)` 不带 marks →
   点 B 后打字 / 在加粗文本中间打字都不带标记。实测 `PAGED marks=[]` vs `NATIVE insertText marks=["strong"]`。
6. **R6** 空历史下撤销/重做 `ok=false`（按钮本就 `disabled`）——预期，非缺陷。分页态历史通道未实测。

**限制（未覆盖）**：happy-dom 无布局 → "是否可见"由 CSS 规则存在性静态推出，需浏览器复核；历史栈、
paged 光标还原、IME 未测。**未改任何源码**（用户只要分析报告）。
