## 用户需求
执行 `P4-执行分批清单.md` 的批 3（性能与可观测 2 项，链式 I5 → I7），每项达到仓库完成定义「导出符号 + 测试（含负例）+ `docs/` 回写 + changeset」后勾选 `[x]`。

## 核心内容
- **I5 性能基准（M，先行）**：根 `bench/` 脚本在 node 环境跑纯函数基准——分页（`paginate` 合成 1000 页量级块）、EPUB 打包（`exportEpub` 合成 50 章文档）、序列化（`serializeNode` 大文档，替代 node 不可行的 DOM 量尺）；基线写 JSON，对比相对变化 >15% 失败，输出 Markdown 报表；`pnpm bench` / `pnpm bench:update` 脚本。
- **I7 可观测性（M，依赖 I5 采集口径）**：core 新增可插拔 `Profiler` 端口（span + 标签）与默认 no-op 实现、按阶段聚合收集器（分页 / 量尺 / 导出 / 自动保存）、`report()` 表格/JSON 可 dump；保留 `PERF_*` 兼容开关；导出链路可选注入 profiler。
- **收尾**：勾选 `P4-执行分批清单.md` 批 3 与 `能力扩展实施计划清单.md` 台账（I5 未开始→已完成、I7 部分→已完成）、门禁行与更新记录，产出一条合并 Conventional Commits 中文提交信息。



## 技术选型
沿用现有栈：pnpm@9 workspace + turbo + vitest 2.1 + tsup；不引入新运行时依赖。bench 脚本为纯 node `.mjs`（受 `.gitattributes` 强制 LF 约束）；Profiler 为 core 纯 TS 模块（零 DOM 依赖，SSR 安全）。

## 实施方案

### I7 可观测性（先行落地采集口径，I5 复用其阶段常量）
- `packages/core/src/perf/profiler.ts`：
  - `PERF_PHASES = { layout: 'layout', measure: 'measure', export: 'export', autosave: 'autosave' }`（bench 与埋点共用同一阶段口径）；
  - `ProfilerSpan` 端口：`span(name, labels?) => { end(extraLabels?) }`（嵌套安全：span 树按 start/end 时间归属）；
  - `createNoopProfiler()`：collect=false 路径，span 返回即时 no-op 对象，零分配零记录；
  - `createCollectingProfiler()`：按阶段聚合 `count / totalMs / minMs / maxMs / meanMs`；`reportJson()` 输出结构化 JSON（含环境字段 node/platform/time），`reportText()` 输出对齐表格，`reset()` 清空；
  - 导出：`Profiler` / `ProfilerSpan` / `ProfilerReport` 类型 + 两个工厂 + `PERF_PHASES`。
- 注入点（均可选、缺省 no-op，关闭时零开销）：
  - `exporter-epub`：`exportEpub` / `exportEpubVolumes` 增 `options.profiler`，在 manifest（opf）、nav、xhtml 序列化、zip 打包各阶段打 span——满足「开启后导出一次 EPUB 得到分阶段耗时表」；
  - `layout`：`paginate` 增可选 profiler（分页阶段 span），缺省不动现有路径。
- vue 兼容：`packages/vue/src/perf.ts` 保留全部既有导出（`PERF_LAYOUT` / `PERF_MEASURE` / `PERF_AUTOSAVE` / `setPerfProbeEnabled` / `isPerfProbeEnabled` / `perfNow` / `perfRecord`）与语义，`setPerfProbeEnabled(true)` 等价开启模块级默认收集 Profiler，`perfRecord` 同时走 `performance.measure`（宿主 PerformanceObserver 兼容）与收集器聚合。

### I5 性能基准（复用 I7 阶段常量）
- 根 `bench/` 目录：`bench/run.mjs`（runner）+ `bench/baseline.json`（基线）+ `bench/report.md`（产物报表）+ `bench/README.md`（口径说明）；
- 基准三组（node 直跑 dist 产物，各预热 1 轮弃样、5 轮取中位数 ms/op）：
  1. `paginate`：合成约 3000 块（混合 1/2 栏）产生 1000+ 页量级；
  2. `exportEpub`：合成 50 章 × 50 段文档；
  3. `serializeNode`：大文档序列化（量尺依赖 DOM 离屏测量，node 以合成输入的分页基准覆盖装箱链路，`docs/18` 说明真实量尺以 demo 侧 `PERF_MEASURE` 数据为准）；
- 基线 JSON 记录 `{ metric: { msPerOp, samples, node, platform, date } }`；对比相对变化 >15% 时非 0 退出并在报表标注（负例：人为改小基线验证失败路径）；node/platform 不匹配时警告不失败（时序噪声防护）；CI 不设 per-PR 门禁，`docs/18` 记录夜间任务可选接法；
- 根脚本：`"bench": "node bench/run.mjs"`（跑 + 对比基线）、`"bench:update": "node bench/run.mjs --update"`（跑 + 重写基线）。

## 架构约束
- 依赖方向不变（bench 在根、只消费各包 dist 公共入口；profiler 由 core 提供、下游可选注入）；
- 不改变任何现有函数签名的必选参数（profiler 均为可选末位选项）；
- no-op 路径零分配零记录（验收：关闭时零开销）。
